# OfferPilot 本地演示路径说明

本文档用于帮助开发者、面试官或评审者在本地快速体验 OfferPilot 的核心能力，尽量以真实前端求职训练场景组织演示顺序。

## 一、演示目标

建议围绕下面这条主线进行演示：

1. 登录系统
2. 查看训练概览
3. 浏览题库并查看题目详情
4. 发起一次模拟面试并体验 SSE 流式反馈
5. 查看该次面试的复盘分析
6. 使用项目包装功能生成项目表述

这条路径能够比较完整地体现项目的产品闭环：

`登录 -> 学习 -> 面试 -> 复盘 -> 项目包装`

## 二、演示前置条件

在开始演示前，建议先确认以下条件已经准备完成。

### 1. 基础服务已启动

推荐使用根目录 `docker-compose.yml` 启动本地依赖：

```bash
docker compose up -d
```

至少需要以下服务可用：

- MySQL
- Redis
- Milvus
- Milvus 依赖组件：etcd、MinIO

### 2. 后端服务已启动

```bash
cd backend
go run ./cmd/server
```

或：

```bash
go run ./cmd/server/main.go
```

### 3. 前端服务已启动

```bash
cd frontend
npm run dev
```

### 4. 环境变量已配置

建议至少检查：

- `frontend/.env.local`
- `backend/.env`
- 根目录 `.env`（如果使用 Docker Compose）

### 5. 数据准备建议

为了让演示更完整，建议本地至少准备以下内容：

- 可登录的测试用户
- 若干题库问题数据
- 可被检索的题库向量数据
- 能正常调用的 LLM / Embedding 配置

如果题库、向量库或模型配置缺失，部分高级能力可能会退化或无法完整体现。

## 三、推荐演示顺序

推荐严格按照下面顺序演示，这样最贴近真实求职准备流程。

1. 登录
2. Dashboard 工作台
3. 题库学习
4. 模拟面试
5. 复盘分析
6. 项目包装
7. 设置页（可选收尾）

## 四、演示路径详解

## 1. 如何登录

### 页面入口

- 打开前端首页
- 默认进入登录页 `/login`

### 建议演示内容

- 输入测试邮箱和密码
- 点击登录
- 说明当前登录已经接入真实认证接口
- 展示登录成功后自动跳转到 `/dashboard`
- 刷新页面，说明登录态可以恢复

### 建议讲解点

- 登录成功后 token 会保存到本地
- 应用初始化时会自动调用当前用户接口恢复登录态
- 顶部导航可以查看用户昵称，并支持退出登录

## 2. 如何体验 Dashboard

### 页面入口

- 登录成功后自动进入 `/dashboard`
- 或从左侧菜单点击“工作台首页”

### 建议演示内容

依次介绍页面 4 个区域：

- 顶部统计卡片
  - 总训练次数
  - 平均分
  - 本周训练次数
  - 当前最大薄弱项
- 最近训练记录列表
- 薄弱知识点图表
- 推荐训练任务面板

### 建议讲解点

- 这里体现的是用户近期训练概览
- Dashboard 已从 mock 切换到真实接口
- 图表和推荐任务可以帮助用户快速判断下一步训练重点

## 3. 如何体验题库页

### 页面入口

- 从左侧菜单点击“题库学习”
- 对应路由：`/question-bank`

### 建议演示内容

建议按下面顺序操作：

1. 在搜索框输入一个关键词
2. 切换分类筛选
3. 切换“高频 / 中频”筛选
4. 观察题目列表变化
5. 点击某一道题打开详情抽屉
6. 演示收藏 / 取消收藏

### 建议讲解点

- 题库查询已经接入真实 API
- 支持关键词、分类、频率的组合筛选
- 当前题库既能作为学习入口，也能作为后续 RAG 的知识来源
- 收藏能力可以作为用户自定义训练池的基础

## 4. 如何发起一次模拟面试

### 页面入口

- 从左侧菜单点击“模拟面试”
- 对应路由：`/interview`

### 推荐演示方式

这是整套系统最重要的演示环节，建议重点讲。

#### 第一步：进入页面并查看布局

页面是三栏结构：

- 左侧：问题列表
- 中间：问答主区域与输入框
- 右侧：状态面板、评分区、知识命中区

#### 第二步：发起或进入一个面试会话

建议说明：

- 当前系统会创建真实 interview session
- 首题由后端通过 LLM 生成
- 会话详情由真实 REST 接口获取

#### 第三步：提交一段回答

在输入框中输入一段回答，然后点击“提交回答”。

此时建议重点观察：

- 右侧 Agent 状态变化
- 中间聊天区的流式输出
- 右侧知识命中区的实时更新

#### 第四步：演示 SSE 流式过程

建议现场说明后端链路：

1. 保存用户回答
2. 检索相关题库知识
3. 拼接 RAG 上下文
4. 调用 LLM 生成反馈和追问
5. 通过 SSE 持续返回 `state / reference / delta / done`

#### 第五步：演示中断能力

如果当前页面支持停止流式输出，可进一步演示：

- 用户主动停止当前流
- 页面如何清理流式状态
- 避免重复连接的保护逻辑

### 建议讲解点

- Interview 是当前项目最完整的闭环能力
- 不只是普通聊天，而是“会话 + 检索 + 评分 + 追问 + SSE”组合
- 右侧 `Knowledge Reference` 展示的是实际检索回来的参考知识片段
- SSE 协议已经统一为：`state / reference / delta / done`

## 5. 如何查看复盘

### 页面入口

- 从左侧菜单点击“复盘中心”
- 对应路由：`/review`

### 建议演示内容

- 查看总体评分
- 查看多维评分雷达图
- 查看知识模块得分柱状图
- 查看最近训练趋势折线图
- 查看学习建议与薄弱点

### 建议讲解点

- 复盘已不再是纯占位数据
- 当前复盘会结合真实会话消息生成分析结果
- 评分维度保持与前端图表一致：
  - technical
  - expression
  - logic
  - depth
  - project
- 如果具备检索上下文，复盘也可结合 reference 信息生成更真实的建议

## 6. 如何体验项目包装

### 页面入口

- 从左侧菜单点击“项目包装”
- 对应路由：`/project-polish`

### 推荐演示方式

建议输入一个你熟悉的前端项目，至少填写：

- 项目名称
- 项目背景
- 技术栈
- 职责与贡献
- 难点
- 成果

然后点击生成。

### 建议展示内容

右侧结果区通常重点看这几块：

- 简历版项目描述
- 面试版项目描述
- 技术亮点
- 难点与解决方案
- 可能追问与建议回答

同时还可以演示：

- 点击复制
- 查看历史记录
- 点击历史记录查看详情

### 建议讲解点

- 当前项目包装已接入统一 LLM service
- 输出结果不是简单模板，而是基于输入材料生成
- 这个模块非常适合作为“求职准备辅助工具”的亮点展示

## 7. 设置页如何作为收尾演示

### 页面入口

- 从左侧菜单点击“设置”
- 对应路由：`/settings`

### 建议演示内容

- 默认面试模式
- 追问强度
- 评分严格程度
- 模型名称
- 流式输出开关

### 建议讲解点

- 设置页体现的是系统可配置能力
- 适合在演示最后说明系统具备后续扩展空间
- 未来可以进一步接入多模型、多面试模式、多策略模板

## 五、适合面试场景的讲解重点

如果这次演示是用于技术面试、项目答辩或作品展示，建议重点突出以下内容：

### 1. 产品闭环

不是只做了一个聊天页面，而是完整覆盖：

- 登录
- 数据概览
- 学习
- 面试
- 复盘
- 项目包装

### 2. 工程边界清晰

可以强调：

- 前端使用 `store + composable + component` 分层
- 后端使用 `handler + service + repository + model` 分层
- LLM、Embedding、Milvus 检索能力有独立基础服务层

### 3. 真实 AI 能力接入

重点说明：

- Interview 已接入真实 LLM + RAG
- Project Polish 已接入真实 LLM 生成
- Review 已接入真实会话分析逻辑
- SSE 流式链路不是假动画，而是实际事件驱动

### 4. 可继续扩展

可以顺势讲未来规划：

- 更完整的 Agent 编排
- 更强的题库管理与知识入库
- Docker 化部署
- 更稳定的结构化输出与评估体系

## 六、演示中的常见注意事项

### 1. 提前准备测试数据

如果没有题库数据、用户数据、会话数据，很多页面虽然能打开，但无法体现完整效果。

### 2. 提前验证模型配置

如果 `LLM_API_KEY`、`EMBEDDING_API_KEY` 或 Milvus 配置有问题，Interview / Review / Project 的高级能力会受影响。

### 3. 尽量避免现场第一次跑索引

如果需要题库向量化，建议提前完成，避免演示时等待过长。

### 4. 演示时优先讲体验，再讲实现

推荐顺序：

1. 先让评审看到产品效果
2. 再补充架构、SSE、RAG、LLM 的实现细节

这样更容易建立整体认知。
